# WXPlayer 1.7.13 implementation plan

> Execution: superpowers:executing-plans, inline. User authorizes the eight changes; only placeholders are approved, red validation borders are not.

**Goal:** Translate SourceWindow faithfully and fix playback layout, searches, provider categories, stable catalogue hero, source persistence and startup Home; replace the application/README logo.

**Architecture:** Keep existing WPF controls, handlers and APIs. Extend the existing scoped Live appearance to all embedded playback/library views. Catalogue categories use the existing query and paging callback, loading additional categories on demand rather than loading every provider category upfront.

**Tech stack:** WPF, C#, .NET 10, existing LibVLCSharp and SQLite.

- New approved copy: address hints for the three kinds; username/password/MAC/XMLTV hints. No duplicated validation or red invalid-field logic.
- Preserve playback engine, native host, fullscreen ownership, stream/recording/EPG logic, provider import, favorites/history and Discord ID. No new dependencies or framework migration.
- Use scoped SourceTheme merged from Utility/Settings; no blur, bitmap text caching or opacity masks.
- Deliver EXE, portable, source and checksum files under E: outputs.

## Review focus
1. Rapid source/category/search changes: cancelled old requests cannot overwrite current catalogue/hero.
2. Missing/deleted last source: deterministic existing fallback; settings remain compatible with old files.
3. Modal add/edit cancel: original objects, entered values, secret privacy and validation exceptions remain intact.
4. Home/catalogue/playback/fullscreen/PiP transitions: controls restore their single original parents and overlay closes cleanly.
5. Empty search/category results and hundreds of categories: all actual chips remain reachable without eager loading all artwork.
